# Mall 系统接口性能测试报告

## 1. 测试目的
评估 Mall 系统登录与品牌列表接口在 50 并发下的性能表现，分析系统资源占用情况。

## 2. 测试环境
- 服务器：阿里云 ECS 2核4G Ubuntu 22.04
- 被测系统：Docker Compose 部署的 Mall 系统
- 压测工具：Apache JMeter 5.6.3 (命令行模式)
- 监控工具：Prometheus + Grafana + Node Exporter

## 3. 测试策略
- 并发用户数：50 线程
- Ramp-up：10 秒
- 持续时间：300 秒 (5分钟长稳测试)
- 循环方式：持续压测，直到时间结束

## 4. 测试结果（核心指标 - 数据来自 JMeter HTML 报告）
| 指标 | Login 接口  | Brand_List 接口 | TOTAL (总体) |

## 5. 系统资源占用分析（基于 Grafana 监控）
- **CPU 占用率**：压测期间 CPU 峰值达到 **99.5%**，系统负载飙升至 **600%**，系统完全处于满载状态。
- **内存占用率**：内存占用稳定在 **47.7%**，无内存泄漏风险。
- **瓶颈结论**：结合 JMeter 的 TPS 曲线（峰值 19.88）和高达 2.4 秒的平均响应时间，
- 可以确认系统受限于 **CPU 算力瓶颈**。2核4G 的 ECS 在同一台机器上承载 Nginx、MySQL、SpringBoot 和 Redis，资源争抢严重。
- **优化建议**：升级 ECS 配置至 4核8G，或拆分 MySQL 到独立实例。

## 6. 测试结论与优化建议
- **测试结论**：在 50 并发、持续 5 分钟的长稳测试下，系统整体极其稳定，错误率为 0%，总 TPS 达到 19.88。但用户体验较差（APDEX 得分仅 0.086），平均响应时间 2.4 秒，远超常规标准（<1秒）。
- **优化建议**：
    1. **纵向扩容**：将云服务器从 2核4G 升级到 4核8G，或独立部署 MySQL 数据库，避免 CPU 资源争抢。
    2. **引入缓存**：品牌列表接口（`/brand/list`）平均耗时 1.5 秒，数据变动频率低，建议引入 Redis 缓存，可将响应时间降至 10ms 以内。
    3. **优化登录逻辑**：登录接口耗时 3.3 秒，建议对 BCrypt 加密参数进行降级（如从 10 降为 8），或在业务层面引入 Token 缓存机制。
    4. **数据库优化**：调整 MySQL 连接池配置（增大 maxActive），排查是否存在慢 SQL 并补充索引。
